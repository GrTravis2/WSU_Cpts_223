### Merge Sort vs Insertion Sort:
- By intuition it makes sense that merge sort would perform better than insertion sort since merge sort has O(log(n)) time complexity, while insertion sort has O(n^2) complexity, but I found this was not always the case during testing. For small sorting calls insertion sort appears to finish significantly sooner when compared to merge sort. There may be several reasons why that is the case. Insertion sort must verify the order of each element and then swap recursively if two elements are out of order, in the best case where the data is sorted this only takes one pass of the container for O(n) time. Its possible that the collections tested are already in order or close to in order! Merge sort differs from insertion sort in that no matter the current order of the data, the merge sort algorithm must break down all the elements in the container into smaller pieces before they are compared. Even if merge sort receives a pre-sorted collection it will not be able to tell and as a result will complete the whole algorithm anyway. Additionally, insertion sort has slightly less overhead than merge sort in that typically less recursive calls to the swap method happen and the algorithm is in place (does not require additional memory allocaton!). Merge sort repeatedly splits the container in half until there are two single elements to compare, and each iteration of the algorithm requires allocating memory and copying over the values to be sorted. Merge sort has more overhead when compared to insertion sort, and making many small memory calls is expensive! Inside my sorting function, I have a variable that measures and prints function call duration in seconds and then outputs the resulting duration and the number of elements. Testing Across several small categories, where the number of elements in the category is less than 10, and insertion sort appeared to win each time. As discussed above, I believe this is due to insertion sort being in place. While merge sort is generally "faster" the difference in the algorithms is not enough to overpower the additional memory allocations and the extra recursive calls. On the other hand, as data sets that are sorted get large, merge sort becomes much faster than insertion sort. Even a collection of 24 elements is enough for merge sort to take the lead. In table 1 below, which compares performance of insertion sort and merge sort over various collection sizes, merge sort is faster around 30 element sorts! As collections grow the difference only gets larger, around 100 elements the difference is about 3/4ths of a second. While I was not able to get the final element count or time, for the largest collections I could test merge sort felt "instant" while insertion sort easily took longer than a second to complete. Sorting and printing category key "Toys & Games" is too long to fit on the command line and cuts off the end, but the difference in run time for the two algorithms is long enough to see the difference if you want to test for yourself!
